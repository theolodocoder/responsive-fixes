Four mobile layout bugs, before and after

A mock dashboard and landing page with the four bugs from your post: the sidebar overlapping content, a pricing calculator cut off under 400px, the signup button hidden by the cookie banner, and form fields wider than the screen. Drag the width slider to check any phone size.

Which one I'd fix first, and why

  1. Signup button under the cookie banner. Ad traffic lands on the landing page, so every hidden signup button is paid traffic lost.
  2. Pricing calculator cut off. It's the next step for someone deciding to buy.
  3. Form fields wider than the screen. They make signup feel broken on small phones.
  4. Dashboard sidebar overlap. It hurts existing customers, not new ones from the campaign, so it goes last this week.

1. Sidebar overlaps the content

The sidebar is positioned on top of the page at every width. Under 768px it becomes a drawer behind a Menu button.

@media (max-width: 767px) { .sidebar { position: fixed; transform: translateX(-100%); } .sidebar.open { transform: none; } }

2. Pricing calculator cut off

A fixed-width table inside a box with overflow hidden. Under 400px each row stacks as a small card with its label.

@media (max-width: 400px) { .calc tr { display: block; } .calc td::before { content: attr(data-label); } }

3. Signup hidden by the cookie banner

The banner is fixed to the bottom and covers the button. The page reserves the banner's real height, measured with ResizeObserver, until it's dismissed.

body { padding-bottom: var(--cookie-h, 0px); } new ResizeObserver(([e]) => root.style.setProperty('--cookie-h', e.borderBoxSize[0].blockSize + 'px') ).observe(banner)

4. Form fields wider than the screen

width: 100% plus padding and border, with content-box sizing and a min-width in a flex row. Border-box sizing and letting the row wrap fixes it.

input, select { box-sizing: border-box; max-width: 100%; } .row { flex-wrap: wrap; } .row > * { flex: 1 1 140px; min-width: 0; }
